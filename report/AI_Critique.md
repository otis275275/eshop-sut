# AI Critique

During this automation testing assignment, I collaborated with Antigravity (Gemini) step by step rather than relying on a single generic prompt. While the AI accelerated test data structuring and Playwright boilerplate generation, several concrete errors and omissions emerged during human review.

First, in `TC-FR12-02`, the AI initially used `page.on('dialog')` combined with a synchronous `expect(alertMessage)` check right after clicking Login. Because the Web Admin login handler triggers `alert()` asynchronously after the `/api/login` HTTP response returns, the assertion executed prematurely and failed across all three browsers. Replacing it with `await page.waitForEvent('dialog')` eliminated the race condition. Second, the AI initially relied on shared seed accounts (`test@eshop.com`) for lockout testing, which would cause cross-browser test pollution once an account became locked on Chromium. Third, when running locally cached browsers, the AI attempted to run an older `firefox-1543` binary against Playwright 1.59, triggering a protocol mismatch until I switched the third project to Microsoft Edge (`msedge`). Finally, the AI could have missed locale-specific currency formatting differences (`.` vs `,`) across browser engines if not explicitly reviewed.

These gaps occurred because LLMs generate code based on static patterns rather than live runtime timing, asynchronous browser events, and local environment state. The key principle I learned is that AI acts best as a fast, disciplined assistant: humans must still design state isolation, verify asynchronous synchronization, and triage real SUT defects from script bugs.
